# Codebase audit, 2026-09-23

Full-repository audit, one week after the 2026-09-16 audit. Six reviewers read
disjoint slices in parallel: the MCP server and Mission Control API, the capture and
sync functions, the AI pipeline and its prompts, the frontend data layer, the
frontend components and UX, and the migrations plus the Markdown docs. Each
reported only what it traced through the call path, and fixed it in place. Findings
that crossed a slice boundary were handed to the owning reviewer. Nothing in this
audit touched the live project; the three new migrations and the function changes
take effect only when applied and deployed.

## What was checked

`npx tsc -p tsconfig.app.json --noEmit` clean before and after. `npx eslint .`: 1
error before (`prefer-const` in `previewAuthStorage.ts`), 0 after.
`node scripts/check-brand-strings.mjs`: failing before (`CookieList.tsx`), passing
after. `node scripts/check-edge-functions.mjs`: passing (225 files).
`npm test`: 112 of 114 files pass. The two failing files, `EditorToolbar.test.tsx`
(1 test) and `ContactTopicsPanel.test.tsx` (7 tests), fail identically on an

earlier the same day, so they depend on timing and machine load. They are listed

## Most serious findings (all fixed)

- **MCP replies could reach the wrong account.** One `McpServer` and one transport
  served every request in an isolate, and replies were matched by JSON-RPC id,
  which every client numbers from 0 or 1. Two concurrent calls with the same id
  swapped results: one user received another user's tool output, and the other
  call hung. Reproduced locally with the deployed package versions. Each request
  now gets its own server and transport; tools are recorded once at startup.
  Build label `2026-09-23-server-per-request`.
- **Database functions readable across accounts.** `match_notes`, `match_media`,
  `match_note_chunks`, `match_claims` and `match_person_documents` run as owner,
  take the account id as an argument and never compared it with the caller.
  Several service-only functions (`deduct_ai_tokens`, `note_ai_input`,
  `cleanup_profile_duplicates`, the note-AI job functions, profile-audit helpers)
  were still executable by `anon` or `authenticated` because only one of PUBLIC,
  anon and authenticated had been revoked. Migration `20260923150000` adds the
  caller check, revokes all three and fails if any function is still open.
  `match_notes` now also honours `ai_visibility`.
- **Cross-account AI spend and writes.** `profile-audit` sweep and backfill ran
  paid audits on every account; `normalize-profile` apply and rollback trusted a
  `user_id` from a review-queue payload the user can write; `review-queue-bulk`
  reverts and `note-chat`'s `add_wikilink` had no owner check;
  `ai-moderate-content` had no authorization at all. All scoped to the caller.
- **Data deleted on a transient error.** `compute-connections` treated a failed
  `match_notes` call as "no matches" and deleted the note's connections;
  `normalizeText` in `profile-audit` stripped non-Latin letters, so different
  Chinese or Cyrillic values counted as duplicates and one was deleted;
  `profile-reconcile` could merge unrelated contacts for the same reason and on
  single first-name aliases.
- **Discord capture accepted any server.** `/capture` is a global command and
  nothing checked the guild; it now only works in the server saved in Settings.

## Other repairs by area

- **MCP and API:** tool errors are flagged `isError`; `get_action_items` queried a
  column that does not exist; `get_entity_context` never returned notes;
  `get_claims`, `search_images`, `get_note_media`, `get_connected_notes`,
  `find_path`, `get_stats`, `get_user_profile`, `get_group` and the collection
  tools now respect "hidden from AI" and trash; graph tools page past 1,000 rows;
  name lookups prefer an exact match and refuse ambiguous ones; `search_brain`
  paging no longer loops. A database error during key lookup now answers 503
  instead of "invalid key". `mc-api-*` stop answering 200 with zeros on errors and
  return 404 for deletes of rows the caller does not own.
- **Capture and sync:** AI failures in Slack and Slack-thread capture no longer
  lose the message; `quick-capture` saves without AI when credits are empty, so
  imports finish; Telegram pairing reports a failed save; GitHub export no longer
  crashes on non-ASCII metadata or overwrites edits made during export; vault
  import keeps note bodies intact; Drive retries failed files and records the
  import before the slow analysis step; `analyze-media` accepts the service key so
  Drive imports get OCR; email-change mails go to the right addresses;
  stopwords match whole words.
- **AI pipeline and prompts:** truncated model replies are flagged and never
  cached as results; note content, web results and MCP output are fenced as data
  and cannot trigger replacement edits; process-note gets today's date, validates
  dates, coerces field types and no longer auto-applies "review" verdicts or
  zero-confidence moments; prompt size and output caps added to the chat
  functions.
- **Frontend data layer:** failed saves, profile edits, relationship writes and
  group actions now show an error instead of failing silently; the AI-credits
  gate explains why nothing happened; out-of-order credit refreshes can no longer
  restore a spent balance; stale caches after edits are invalidated; realtime
  topic channels no longer die when a person is reopened quickly.
- **UI and UX:** the Slack setup page showed the wrong URL (`slack-capture`
  instead of `ingest-thought`); archived groups can be restored; drafts no longer
  carry over between groups or World entities; Settings tab links work from inside
  Settings and the avatar has a visible "Picture" tab; collection trees load past
  1,000 items; destructive actions use an in-app confirm dialog instead of
  `window.confirm`; about 57 icon-only buttons and 36 inputs got accessible
  names; hover-only controls are reachable by keyboard and touch.
- **Migrations and config:** `wiki_log` now accepts the operations `wiki-cleanup`
  writes (`20260923150200`); indexes on foreign keys that cascade on note delete
  (`20260923150100`); `config.toml` pins `verify_jwt` for all 90 functions, so a
  deploy cannot switch the gateway check on for `gdrive-webhook` or `link-note`.
- **Docs:** `TEST_SCENARIOS.md` matched against the UI (about 110 labels, routes
  and flows corrected); README, CONTRIBUTING, ARCHITECTURE, PROJECT_STRUCTURE,
  DATA_MODEL, CRON_JOBS and UX_BACKLOG brought in line with the code.
