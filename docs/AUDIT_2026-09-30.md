# Codebase audit, 2026-09-30

Full-repository audit the night after the one fact store went live
(`docs/plans/one-fact-store.md`, section 8). Five reviewers read disjoint slices in
parallel: the fact store and everything that reads or writes facts; the People,
profile and review-queue pages; production as it runs (logs, cron, job tables);
every other edge function (split again into capture, sync, note AI, chat and wiki,
API and admin); and the rest of the frontend. A sixth pass looked at the live
catalogue for functions and policies that answer for other accounts. Each finding
was traced through the call path, fixed in place and covered by a test that fails
on the old code, unless listed under open items. Production was only read, as
counts and structure, except for the deploy described at the end.

## Most serious findings (all fixed)

- **Notes about a sensitive person were never hidden.** Every writer stores
  `notes.metadata.matched_people` as objects (`{name, contact_id, canonical_name}`;
  live, all 3,206 entries on 1,015 notes). The checks in `_shared/mc-visibility.ts`
  (added 09-23), `menerio-mcp/_ai_visibility.ts`, `_shared/read-tools.ts` and
  `conversation-chat` compared each entry as an id string, and the SQL function
  `ai_can_see` cast each entry to uuid. So the rule never matched, and the first
  account to mark anyone sensitive would have had `update_note` and `trash_note`
  fail on every note that names someone. One reader now exists
  (`matchedContactIds`), and `ai_can_see` reads `contact_id` without a cast
  (`20260929203000`). Mirrored mission control files are exempt from the
  sensitive-person rule in the REST API: they are copies of Mission Control's own
  files, and 597 of 1,223 name someone, so the mirror sync would have broken.
- **Visibility helpers answered for any account.** `ai_can_see`, `ai_hidden_counts`,
  `mcp_sensitive_person_ids` and two wrappers are SECURITY DEFINER, take an account
  id, and were executable by every signed-in account: counts of another account's
  hidden items and the ids of its sensitive people. Service role only now.
- **Opening and autosaving a note changed it.** Run against all 1,544 live notes,
  the old Markdown converter lost text from 318 of them on a plain open and save
  (fenced code, text in angle brackets) and 743 kept changing on every save
  (tables gained a column each time). The new converter loses text from 20 and
  drifts on 23, every one of which the old one also damaged; none is worse. A
  42-case round-trip suite pins it.
- **GitHub sync overwrote notes with each other.** Two notes with the same title
  in one folder shared a file, and the next pull copied one note's text into the
  other; a pull pushed over a conflict it had just found; a failed export was
  marked synced; trashing a note could delete another note's file; vault import
  dropped every folder, so the next export emptied the Obsidian folders.
- **Assistants reached hidden and sensitive material** through `mc-api-world` (past
  1,000 hidden people, or a 500 past a few hundred), `mc-api-notes` and
  `mc-api-actions` writes, `mc-api-contacts` writes, `mc-api-stats` tags, the entity
  tools, `get_user_profile` with `scope: private`, ambiguous-name lists,
  `note-chat`, `find-connections`, the group AI functions, the Lexicon and digest
  prompts, moment extraction and person enrichment.
- **Collections orphaned their data.** Renaming a field changed its key, so every
  item lost that value; saving an item deleted keys the form did not show.
- **A shared note could draw a sign-in form on the site** (the sanitizer kept
  `form`, inputs and free `style`), and chat replies loaded Markdown images without
  a click, so text planted in a note could send note content to an outside address.
- **Google Drive sign-in accepted any return address**, so an authorization code
  for someone else's Drive could be collected by a page of the attacker's choosing.
  Only the app's own callback page is accepted now.

## Found running in production (logs, 48 hours)

- Admin signup e-mails had failed since 2026-05-14: the trigger read a setting that
  does not exist, so `notify-admin` got no key (401). It now goes through
  `internal.call_edge` (`20260929201100`).
- Deleting a relationship from the server raised `record "old" has no field
  "contact_id"`, so `profile-reconcile`'s batched deletes removed nothing
  (`20260929201000`).
- `wiki-ingest` answered 500 for an exhausted allowance, which closed one of the
  AI worker's two slots each time (126 in 24 hours). It now answers 402, 503, 409
  or 422 as `process-note` does.
- Two autosaves close together both inserted the same wikilink row (409), losing
  the batch. People's names were written to logs by `process-note`.
- Outside this repository: a client still calls `menerio-mcp` with a key revoked on
  2026-09-22 (118 refusals in 24 hours, Claude Code and a Python client), and an
  old Mission Control checkout calls the removed `hub-api-world` every hour.

## Other repairs by area

- **Fact store:** a backdated value no longer stays current beside a later one; a
  "do not suggest again" list and `readFacts` read past 1,000 rows;
  `generate-profile-suggestions` no longer re-suggests private facts or logs the
  model's reply; `profile-lint` and `profile-reconcile` ignore merged and hidden
  contacts; `add_claim` gives one answer for every subject it may not touch.
- **People and profile pages:** "Fix a mistake" to an existing value, a private
  section with facts, a custom section in non-Latin script and a duplicate
  relationship now explain themselves instead of showing a database error; dates
  follow the profile's time zone, which the app now takes from the browser once
  while it is still the UTC default (12 of 13 accounts were); history rows can fix
  a future date or undo "No longer true"; groups count and list all their members,
  not only the ones scrolled into view; accepting a suggestion that fails to save
  keeps it.
- **Capture:** Slack saves the message before any AI step; Discord settles two
  accounts with the same app by the bot token; Telegram takes its secret in the
  header Telegram sends (the URL form still works for the one paired connection
  registered that way); database errors answer 503 instead of 401.
- **Note AI and chat:** a claim the database refuses no longer fails the whole job
  on every retry; non-Latin notes get search chunks; `compute-connections` and
  `recompute-all-connections` no longer delete links past 1,000 notes; chat
  summaries run after the reply, every eight messages, not on every turn; the
  router drops `temperature` for models that reject it; the vision model moves
  off Pixtral 12B (`20260929202000`).
- **Accounts and moderation:** a trashed note is no longer public through its
  link; a suspended account can no longer share by writing the row itself
  (trigger, `20260929203000`); account deletion removes the role and profile only
  after the login is gone; two moderation runs no longer double a strike.
- **Frontend:** the stale-tab self-heal no longer wipes every cache and reloads
  twice on each ordinary deploy; a token refresh no longer reloads open forms over
  unsaved input; about a dozen empty states that were really failures now say so;
  twelve copy buttons that claimed success without copying; a sync-conflict
  indicator in the note editor; dead components removed.
- **Tests and CI:** the `database-permissions` job had failed since 2026-09-20
  because an earlier step created `service_role` without BYPASSRLS; the two
  "timing-dependent" test files hung in the test DOM library (`:modal` selector
  recursion in nwsapi 2.2.27) and now take seconds.

## Checks

`npx tsc -p tsconfig.app.json --noEmit` clean. `npx eslint .`: 0 errors, 1,380
warnings (CI allows 1,453). Brand-string check, edge-function check (267 files),
`check-no-profile-entry-writes`, `check-no-prod-data` pass. The five migrations
were rehearsed on production in one transaction that ended in a raised error:
the World view kept all 15 relationships, marking a person sensitive hid both of
their notes without an error, a machine delete of the 2 hand-edited
relationships was refused without an error, and nothing remained afterwards.

## Open items

Needs a decision:
- `add_claim` still tells an assistant that a private section holds a value
  ("already recorded"). Refusing, or one blank answer, is a product choice.
- A merge does not carry "sensitive" or "hidden" to the surviving contact.
- `process-note` sends notes hidden from AI to the metadata model and the
  embedding service (by design since 09-07; the UI says otherwise).
- `github-sync-scheduled` has no cron job, so notes from MCP, the capture bots and
  the AI reach GitHub only on a manual sync.

Not fixed yet:
- A review-queue Revert does not reopen the value it closed (`writeFact` would
  have to report what it closed).
- `mc-api-world` still filters moments with sensitive people through a URL list.
- Drive: channels are never stopped (no `resourceId` stored), disconnect keeps the
  gateway grant, and the two-minute run handles every account in one invocation.
- Bulk GitHub export re-pushes every note and cannot finish on large vaults;
  vault import re-fetches every file before its skip check.
- `openRouterWithCredits` throws away a paid answer when the deduction fails;
  `wiki-ingest` fails on Lexicons over 1,000 pages; `weekly-review` reads unbounded.
- Old sync-log entries may still share one GitHub path; they are skipped and
  reported as `shared_path`. Detection query:
  `SELECT user_id, github_path, count(*) FROM github_sync_log WHERE entity_type='note' GROUP BY 1,2 HAVING count(*)>1;`
- `generate-contact-profile-suggestions` exists only in production, reads the
  retired `profile_entries` and has no callers.
- This machine's `node_modules` was installed without the lockfile; `npm ci` fixes it.
